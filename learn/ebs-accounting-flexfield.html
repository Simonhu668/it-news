EBS 会计键（Accounting Flexfield）操作指南

给 Application Manager 的实操手册。会计键是 EBS 财务的"地基"——动它之前，先看懂这五节。

1. 会计键是什么

一套"科目编码规则"会计键就是会计弹性域（Accounting Flexfield）。它由几个段（Segment）组成，比如公司段、成本中心段、科目段；每段取一个值，拼起来就是一个完整的科目组合。每个组合在总账里有一个唯一的数字 ID，叫 CCID（Code Combination ID）。记住：凭证行、日记账行存的都是 CCID，那一长串"101-2001-600101"只是给人看的。
场景财务让你"查一下 101-2001-600101 今年的余额"——先按段翻出它的 CCID，再去余额表按 CCID 查；拿着段文本直接去捞，又慢又容易错。

2. 段、值集、值：三层结构

  • 段编码的一节；每段挂一个值集（Value Set），值集决定这段"允许填什么、怎么校验"
  • Independent独立验证：固定白名单
  • Dependent相关验证：父子联动
  • Table表验证：从表里动态取
值在哪维护GL 超级用户 → 设置 → 财务 → 弹性域 → 密钥 → 段值。运维铁律：只加值，不加段——加一段是改会计科目表结构，影响全账套。
场景业务说"成本中心要加两个"——这是加值，半小时搞定；但如果他说"要加一段产品线"，那是改结构，先拉上财务做影响评估。

3. 两条硬卡控

第一条：交叉验证规则（Cross-Validation Rule）管"哪些段值组合不许存在"。违反的组合，保存、过账时直接被拦下。加规则：System Administrator → 设置 → 财务 → 弹性域 → 键 → 规则（先确认会计科目表结构上已勾选"交叉验证"：设置 → 财务 → 弹性域 → 键 → 段，解冻→勾选→冻结→编译），先在测试环境验证再上生产。
第二条：安全规则（Security Rule）管"谁能用哪些段值"。同一套科目，不同职责能用的段值范围可以不同。两者的分工要记牢：交叉验证是全局的"能不能存在"，安全规则是按职责的"谁能用"。
场景别争"科目归谁管"：写一条交叉验证规则让错误组合根本进不了系统，再配安全规则让各部门只能用自己的段值——标准落地成系统硬规则。

4. 动态插入（Dynamic Inserts）

一个开关会计弹性域有个开关"允许动态插入"。开了：用到新科目组合时，系统自动建 CCID；关了：必须先手工建好组合，否则保存就报错。运维建议：生产环境关掉——新组合先审批再建，防止科目体系失控；测试环境可以开着省事。动态插入关了之后，新组合只能从科目组合表单手工建：GL Superuser → 设置 → 科目 → 组合。
场景月结前发现有人在生产环境随手拼了个新组合还过了账——先查动态插入是不是开着；开着的话，这就是科目失控的入口，关掉它。

5. 常见操作清单

  • 查科目组合按段去 GL_CODE_COMBINATIONS 翻 CCID（只读 SQL，join 余额表都用它）
  • 加段值GL 超级用户 → 设置 → 财务 → 弹性域 → 密钥 → 段值，按值集类型维护
  • 开关会计期间Open and Close Periods：Open → Closed 是月结动作；Permanently Closed 是年结后才点的，点了回不来
排错四步
  1. 段值在不在值集里（LOV 选不到先查值集类型）
  2. 是不是被交叉验证拦了——报错是某条规则的自定义错误消息（去"键 → 规则"表单对一下），不是 APP-FND-00668
  3. 新组合 + 动态插入关了 → 报错"组合不存在"，去科目组合表单（设置 → 科目 → 组合）手工建
  4. 出现 APP-FND-00668（"定义弹性域的数据可能不一致"）→ 查的是定义不是数据：段/值集改完有没有冻结+编译，段限定词全不全（常伴随 APP-FND-00992）
场景用户新建科目组合保存报错，别先找开发——按上面四步走，九成是段值、规则、动态插入、定义编译四者之一。
