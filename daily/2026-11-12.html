远程支持工具成攻击跳板：ScreenConnect 攻击活动已波及 6 家服务商、286 台终端

安全厂商 Huntress 11 月 11 日发现，攻击者利用已入侵的服务商 ScreenConnect 环境，通过其 Run Command 功能向客户终端批量部署攻击者自有的 ScreenConnect 客户端，获得独立于服务商合法环境的远程访问；已确认 6 家服务商受害、286 台以上终端、47 个组织受影响，数字仍在上升。攻击者疑似通过被盗凭据与被劫持的支持会话进入服务商环境，初始入侵方式尚未确认；Huntress 还警告攻击者可能在技术员与受感染设备建立会话时反向入侵技术员工作站，该手法机制未明。ConnectWise 11 月 11 日确认正在调查，提醒合作伙伴避免与疑似受感染设备建立交互式会话，并检查账户活动、撤销会话、重置凭据、核查多因素认证。Huntress 已公布入侵指标，包括攻击者中继 185.99.255.28 与两个流氓客户端 ID。使用远程支持工具的组织需关注，核查 Run Command 历史与已公布的入侵指标，暂勿与可疑设备建立交互式远程会话。最新进展：Huntress 11 月 11 日 23:34（美国东部时间）更新分析，活动与第三方扩展 RMM+ 有关：1.0.31 与 1.0.32 版本在管理员未配置访问密钥时接受空白密钥，绕过 ScreenConnect 的账户、角色与多因素认证；受影响终端数更新为 288 台、48 个组织，全部在约 90 分钟内被波及。ConnectWise 11 月 11 日发布公告，称未发现自身系统被入侵或 ScreenConnect 本身存在缺陷，已在约 400 个合作伙伴环境中禁用 Labtech Plus、RMM Plus、RMM+ 等 5 个相关扩展，本地部署的合作伙伴须自行禁用；初始入侵方式与完整范围仍在调查中。Huntress 另指出，工具包中设计的从技术员工作站窃取会话 Cookie 并扩散的步骤尚未观察到成功案例。 最新进展（11月13日）：Huntress 与 Blackpoint Cyber 11 月 12 日分析了攻击者部署的蠕虫式工具包 SCKit：16 个脚本与组件，RelayTrap 组件替换受感染终端上的 ScreenConnect Guest 进程，等待技术员建立会话后尝试利用已修复的客户端文件传输缺陷 CVE-2026-84869（26.6.5 版已修复）向技术员工作站反向发送恶意文件，再窃取浏览器中的 ScreenConnect 会话 Cookie 劫持管理会话、经 Shared Toolbox 向更多终端分发命令。两家厂商均未观察到该扩散手法成功：Blackpoint 在最新客户端上复现时修复阻止了执行，Huntress 检查的日志中控制台接管尝试全部失败。建议：禁用相关第三方扩展、更新 ScreenConnect 客户端、核查 Run Command 与 Toolbox 活动，避免与疑似受感染设备建立交互式会话。

推荐理由：与什么工作有关：远程支持与终端运维，远程访问工具一旦被盗用，攻击者无需攻破客户原有系统即可批量进入。值得带走什么：排查起点是 Run Command 执行历史与已公布的客户端 ID，而非等告警；重置被盗密码清不掉已装好的流氓客户端。什么条件下适用：使用 ScreenConnect 或同类远程支持工具的组织须核查；未使用的组织可把本条作为第三方远程访问权限盘点案例。

车间与 ERP 之间重复录入的消除方法：先定数据归属，再建同步
