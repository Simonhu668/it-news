GitLab 10 月 21 日发布修复，编号 CVE-2026-110264，CVSS 满分 10.0：特定条件下，未登录的攻击者可在自托管 GitLab 服务器上执行任意代码。根因是其打包发布的 Ruby 正则引擎 Onigmo 在编译特制正则表达式时发生整数溢出。由于 GitLab 自己打包并修复该引擎，缺陷存在于自 2014 年 7.0 以来的每一个版本。修复覆盖 7 个版本分支：19.5.1、19.4.3、19.3.6、19.2.9、19.1.9、19.0.10、18.11.13，其中 4 个已超出 GitLab 常规支持策略（只覆盖当前加前两个月度版本），是其为严重问题保留的回迁做法。值得注意：10 月 12 日的更新只修了同引擎的另一个 10.0 漏洞 CVE-2026-97229（覆盖 19.2 及更新），新修复版恰比那次高一级，所以 9 天前刚打过补丁的实例仍在影响范围，须再升级。GitLab 称截至 10 月 22 日未发现该漏洞被利用，也未进入 CISA KEV；但 GitLab 没有说明攻击者需要哪些前提条件，也没有给出临时缓解办法，升级是唯一官方修复。随修还发布了两条 Sigma 检测规则，可在应用日志中排查利用痕迹。同批共修 11 个安全问题，另有两处高危：CVE-2026-15723（8.2，SAML+LDAP 自动关联开启时登录用户可接管他人账户）、CVE-2026-112212（7.5，OAuth/OIDC 端点在共享缓存场景下的缓存投毒）。升级代价：19.4.3 与 19.3.6 包含数据库变更，单节点升级期间会停机，多节点可走零停机流程。

原文

GitLab released fixes on October 21 for a flaw that lets an attacker run code on a self-managed server without logging in, and it affects every version of the software going back to 7.0, released in 2014. The fix matters even for administrators who patched nine days earlier: the October 12 update covered only versions 19.2 and later, and the new fixed versions sit one patch above it, so an instance updated then is in range again. The flaw, tracked as CVE-2026-110264, is rated 10.0 on the CVSS scale, the maximum. GitLab says that, under certain conditions, it could allow an unauthenticated user to run arbitrary code on the server due to an integer overflow during the compilation of a specially crafted regular expression. GitLab has not said what those conditions are. The company reports no sign the flaw has been used in attacks, and it is not listed in the U.S. CISA catalog of known exploited vulnerabilities as of October 22. Only self-managed installations need to act. GitLab.com already runs the fixed version, and GitLab Dedicated tenants on the internal releases 19.3.5-internal0 and 19.4.2-internal0 or later already have the fix. GitLab fixed the flaw in seven versions at once: 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10 and 18.11.13. The reason the flaw reaches so far back is the part of GitLab that failed. The regular-expression compiler is Ruby's built-in engine, called Onigmo, which GitLab ships inside its own packages and patches in its own builds. A weakness in that engine is present wherever GitLab has shipped it, which is every release since 7.0. GitLab also published two detection rules to help self-managed administrators look for exploitation attempts, named "Onigmo native worker crash" and "Org mode render error burst." They are part of the company's open-source TLDR framework, which writes each detection in the Sigma format against GitLab's own application logs. GitLab has not said what preconditions an attacker needs to reach the compiler, so administrators cannot yet rule themselves out by configuration; the fix is the only certain protection, and GitLab's advisory offers no interim workaround. This is the fourth code-execution flaw in GitLab's regular-expression engine that the same researcher, who uses the handle joaxcar, has reported in a month, and the first to reach versions before 19.2. The upgrade carries a cost worth planning for. The 19.4.3 and 19.3.6 releases include database changes that run during the upgrade, and on a single-node server that means downtime while they finish. GitLab says multi-node setups can apply the patch without downtime using its zero-downtime procedure.
