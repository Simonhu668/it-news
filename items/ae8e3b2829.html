正文 · AI 翻译

微软已修复 Azure App Service for Linux 中的一个最高严重级提权缺陷，未经认证的攻击者可通过网络提升权限；微软表示客户无需采取任何操作即可受到保护。

该缺陷编号为 CVE-2026-109484，属于特殊元素注入弱点（CWE-75），CVSS 3.1 基础分为 10.0，即最高分。微软将其归类为提权缺陷，最高严重级为严重。

微软安全更新指南显示，该公告发布于 2026 年 11 月 19 日星期四；对应的 CVE 记录于 2026 年 11 月 24 日星期二公开，并标注为“仅托管服务”，即修复由微软在平台侧应用，而非以客户安装的更新形式发布。

截至 2026 年 11 月 25 日，CVE-2026-109484 的修复已包含在 Azure App Service for Linux 的 110.0.7.78 与 111.0.7.3 版本中；尚无公开利用代码，该缺陷也未列入 CISA 已知在野利用漏洞目录。

微软对 CVE-2026-109484 的描述只有一句话：未能对注入到另一平面的特殊元素做净化，使得未授权攻击者可在网络上提升权限。CWE-75 描述的是软件把攻击者提供的输入未经处理传入另一层（如命令、查询或控制通道）的情况，接收组件随后把部分数据解释为指令，攻击者便可以该组件的权限行事。

该缺陷的 CVSS 向量为 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H：攻击通过网络进行，无需特殊条件、无需账号、无需用户操作，且影响超出存在缺陷的组件本身（范围已改变）。成功攻击会造成机密性、完整性与可用性的重大损失。

微软未说明是 App Service for Linux 的哪个组件处理了未经净化的输入、涉及哪类特殊元素，也未说明攻击者可达到的权限级别；公告未点名研究人员，也未解释攻击者是否可能从一个客户的应用跨入另一个租户的资源。

受影响版本方面，根据微软的 CVE 记录，Azure App Service for Linux 从 110.0.0.0 起、到 110.0.7.78 之前受影响；安全更新指南列出 110.0.7.78 与 111.0.7.3 为包含修复的版本号。这些是微软在其基础设施上运行的平台版本，不是客户下载的软件包版本。微软公告称 CVE-2026-109484“无需客户操作即可解决”，安全更新指南中也没有可供客户安装的更新或知识库文章。

CVE-2026-109484 是微软在 2026 年针对 Azure App Service for Linux 提交的第二条 CVSS 10.0 的提权记录。2026 年 7 月，微软披露了 CVE-2026-58630，即 Azure Stack Hub 上 Azure App Service 的不当访问控制缺陷（CWE-284），同样为 10.0 分。

在野利用方面，尚无来源报告针对 CVE-2026-109484 的攻击。微软的时间 CVSS 分为 8.7，反映利用代码成熟度为“未证实”，即没有公开可用的利用代码或仅存在理论上的利用；同一评分同时记录官方修复已发布、报告已确认。截至 2026 年 11 月 25 日，CVE-2026-109484 未列入 CISA 已知在野利用漏洞目录。

微软表示，Azure App Service for Linux 客户无需安装更新、更改配置或重启应用即可受到保护；由于修复已在服务端就位，微软未列出变通办法或缓解措施。微软未发布入侵指标，也未说明在修复前是否发现滥用迹象。希望额外确认的团队可以检查 App Service 与 Azure 活动日志中的异常管理操作，不过微软并未针对 CVE-2026-109484 推荐这样做。

CVE-2026-109484 与 Azure App Service 在 2026 年 11 月 18 日与 19 日推出的 NGINX2Root 更新无关：那次更新修补了内置 PHP 与 WordPress Linux 镜像中的 NGINX，微软的相关文章未提及 CVE-2026-109484。运行自定义容器的客户仍需用修复的 NGINX 版本重建镜像；App Service 用户可通过 SSH 执行 nginx -v 或使用 az webapp exec 检查运行版本。

原文

Microsoft has fixed a maximum-severity privilege-escalation flaw in Azure App Service for Linux that let an unauthenticated attacker elevate privileges over the network, and says customers do not need to take any action to be protected.

The bug, tracked as CVE-2026-109484, is a special element injection weakness (CWE-75) and carries a CVSS 3.1 base score of 10.0, the highest possible rating. Microsoft classes it as an Elevation of Privilege vulnerability with a maximum severity of Critical.

Microsoft's Security Update Guide lists the advisory as released on Thursday, November 19, 2026. The matching CVE record went public on Tuesday, November 24, and is tagged "exclusively-hosted-service", meaning the fix was applied on Microsoft's side of the platform rather than shipped as an update for customers to install.

As of November 25, the CVE-2026-109484 fix is in builds 110.0.7.78 and 111.0.7.3 of Azure App Service for Linux, there is no public exploit code, and the flaw is not in CISA's Known Exploited Vulnerabilities catalog.

Microsoft's description of CVE-2026-109484 is one sentence: failure to sanitise special elements into a different plane in Azure App Service allows an unauthorised attacker to elevate privileges over a network.

CWE-75 describes software that passes attacker-supplied input into another layer, such as a command, a query or a control channel, without neutralising the characters that layer treats as instructions. The receiving component then interprets part of the data as a command, so the attacker can act with that component's privileges instead of their own.

The CVSS vector for CVE-2026-109484 is CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H. In plain terms, the attack works over the network, needs no special conditions, no account and no action from a user, and its impact reaches beyond the vulnerable component (the "Scope: Changed" metric). A successful attack results in significant loss of confidentiality, integrity, and availability.

Microsoft has not said which App Service for Linux component processed the unsanitised input, what kind of special elements were involved, or what privilege level an attacker could reach. The advisory names no researcher, and it has not been explained whether an attacker could cross from one customer's app into another tenant's resources.

According to Microsoft's CVE record, Azure App Service for Linux is affected from build 110.0.0.0 up to, but not including, 110.0.7.78. The Security Update Guide lists 110.0.7.78 and 111.0.7.3 as the build numbers carrying the fix.

These are platform builds that Microsoft runs on its own infrastructure, not package versions that customers download. Microsoft's advisory states that CVE-2026-109484 "requires no customer action to resolve," and the Security Update Guide shows no customer-installable update or knowledge base article for it.

CVE-2026-109484 is the second CVSS 10.0 privilege-escalation record that Microsoft has filed against Azure App Service for Linux this year. In July, Microsoft disclosed CVE-2026-58630, an improper access control flaw (CWE-284) in Azure App Service on Azure Stack Hub, which also carried a 10.0 score.

No source reports attacks using CVE-2026-109484. Microsoft's temporal CVSS score of 8.7 reflects an exploit code maturity of "Unproven", which Microsoft defines as no publicly available exploit code or an exploit that is only theoretical. The same score records an official fix as available and the report as confirmed.

As of November 25, CVE-2026-109484 is not listed in CISA's Known Exploited Vulnerabilities catalog. Vulnerability tracker OffSeq reports no exploit in Metasploit or Exploit-DB, no Nuclei template, and no attack traffic on its honeypot sensors. The National Vulnerability Database has not yet completed its own analysis of the flaw.

Microsoft says Azure App Service for Linux customers do not need to install an update, change a configuration or restart apps to be protected against CVE-2026-109484. Microsoft lists no workarounds or mitigations because the fix is already in place on the service.

Microsoft has not published indicators of compromise or said whether it found signs of abuse before the fix. Teams that want extra assurance can review App Service and Azure activity logs for unexpected administrative actions, though Microsoft has not recommended this for CVE-2026-109484.

CVE-2026-109484 is separate from the NGINX2Root updates Azure App Service rolled out on November 18 and 19. That work patched NGINX in the built-in PHP and WordPress Linux images, and Microsoft's post about it does not mention CVE-2026-109484. Customers running custom containers still need to rebuild with a fixed NGINX release for those flaws; App Service users can check the running version with `nginx -v` through SSH or `az webapp exec`.
