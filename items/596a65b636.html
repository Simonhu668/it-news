AXO Technologies 11 月 6 日发布的教程介绍一个小型 Power Automate 流程：供应商把送货单 PDF 发到共享业务邮箱，流程按主题词筛选附件并存入 SharePoint 的“待审核”文件夹，审核仍由人工按采购订单与数量核对，流程只负责收文件，不做审批、不证明附件安全。教程以一家马来西亚柔佛分销商的假设试点为例：请两家常供货商把主题含“Delivery Note”的送货单发到专用邮箱，试点把匹配的 PDF 存入内部待审核文件夹。搭建分三步：先核对账号与目标位置——使用专用的 Exchange Online 共享邮箱与已有的 SharePoint 文档库，提前建好收件文件夹；Office 365 Outlook 连接背后的工作账号须有已授权的 Exchange Online 邮箱并对共享邮箱有完全访问权限，仅有“代发”权限不能读取；SharePoint 连接身份须有在目标位置创建文件的权限，审核人只给工作所需的访问权限，并检查文件夹的继承访问范围，避免把供应商单据放进广泛共享或外部访客可访问的库；同时确认制作者可在所选环境中创建流程，且组织的数据策略允许两个连接器配合使用。两个连接器均为标准连接器，符合条件的微软 365 或 Office 365 权益一般可覆盖此类标准连接器云端流程，无需 Copilot 附加许可；邮箱容量较大或用到部分高级功能时可能需要单独的邮箱许可，须另行核对。第二步搭建窄口径收件流程：在 Power Automate 中新建自动化云端流程，选用 Office 365 Outlook 触发器“当共享邮箱收到新邮件时（V2）”，填入共享邮箱地址并选择收件箱，把“仅带附件”与“包含附件”设为是，并按约定短语过滤主题；对触发器的附件集合使用“应用到每一项”，在其中加条件只保留附件名转小写后以 .pdf 结尾的文件，跳过触发器标记为内嵌的附件；匹配分支中添加 SharePoint“创建文件”操作，选定站点与已有收件文件夹，文件内容使用当前附件的内容字节而非邮件正文或附件 ID；试点阶段在附件名前加 guid() 生成的标识符再加连字符，以减少同名文件冲突；SharePoint 不接受的文件名应转人工复核。生成的前缀能分隔同名文件，但重放也可能产生另一份副本；如下游动作不容忍重复，须增加以稳定的消息与附件标识符为键的持久收件记录，并在启用下游动作前强制唯一。第三步先测异常再依赖流程：发送合成测试邮件——一份有效 PDF、两份同名 PDF（分开发送）、一封带签名图片的邮件、一封无关主题邮件，检查运行记录并打开保存的 PDF 确认可读；请有权限的审核人确认访问范围，并用无库权限的普通账号确认文件未被过度共享。微软文档指出，共享邮箱触发器会跳过超过管理员限制与 50 MB 两者中较小值的邮件，也可能跳过受保护邮件或无效附件；Outlook 连接器还提示，在突发流量下触发器内获取附件内容可能超时。教程建议把试点定位为收件辅助，保留人工对账渠道并约定由谁检查失败运行与无匹配文件的邮件；流量增大时，可改用带共享邮箱上下文的单独“获取附件（V2）”操作拉取内容；指定备用维护人并记录连接与权限，待有人调岗时复核；先以一个收件箱与一个库跑试点，再扩展。

原文

AXO Technologies published a how-to on November 6, 2026 for a small Power Automate flow that saves supplier PDFs from a shared mailbox into SharePoint. A supplier sends a delivery note to the shared operations inbox; the flow files matching PDFs into a controlled SharePoint library and leaves the decision about each file to the operations team. The hypothetical example is a Johor distributor asking two regular suppliers to send delivery notes to a dedicated mailbox with 'Delivery Note' in the subject; the pilot saves matching PDFs into an internal Pending Review folder, while staff still check the purchase order and quantities before accepting a delivery. The flow saves the file; it does not approve a transaction or certify that an attachment is safe. Step 1 is checking accounts and destination: start with a dedicated Exchange Online shared mailbox and an existing SharePoint document library, and create the intake folder before building the flow. The work account behind the Office 365 Outlook connection needs a licensed Exchange Online mailbox and Full Access to the shared mailbox; Send As alone does not provide read access. The SharePoint connection identity needs permission to create files at the destination; give reviewers only the access their jobs require and check who already inherits access to the folder. Confirm the maker can create flows in the selected environment and that the organization's data policies allow the two connectors together. Microsoft classifies Office 365 Outlook and SharePoint as standard connectors, so an eligible Microsoft 365 or Office 365 entitlement can cover this standard-connector cloud flow, with no Copilot add-on needed. Step 2 builds a narrow intake flow: create an automated cloud flow with the Office 365 Outlook trigger 'When a new email arrives in a shared mailbox (V2)', enter the shared mailbox address, select Inbox, set Only with Attachments and Include Attachments to Yes, and filter by the agreed subject phrase. Apply to each attachment, keep only names ending in .pdf after lowercasing, and skip inline attachments. In the matching branch, add SharePoint Create file, select the site and the intake folder, and use the current attachment's content bytes, not the message body or attachment ID. For the pilot, prefix the attachment name with a generated identifier such as guid() plus a hyphen to reduce collisions between suppliers using names like delivery-note.pdf, and route names SharePoint does not accept to manual review. A generated prefix separates same-named files but also lets a replay create another copy, so if duplicates would cause downstream work, add a durable intake record keyed by a stable message and attachment identifier and enforce uniqueness before enabling that downstream action. Step 3 is testing exceptions before relying on the flow: send synthetic test messages — one valid PDF, two PDFs with the same filename in separate messages, a message with a signature image, and an unrelated subject — then check run history, open the saved PDFs to verify they are readable, have an authorized reviewer confirm access, and use an ordinary account without library permissions to check files are not visible more widely than intended. Microsoft documents that the shared mailbox trigger skips messages larger than the lower of the administrator's limit and 50 MB, and may skip protected messages or invalid attachments; the Outlook connector also warns that fetching attachment content in the trigger can time out during bursts. Treat the pilot as intake assistance, keep a manual reconciliation route, agree who checks for failed runs or messages with no matching file, and assign a backup maintainer and document the connections and permissions to check when someone changes role. Run the pilot with one inbox and one library before expanding.
