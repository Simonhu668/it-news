Windows 事件 ID 取证速查：从日志还原机器上发生过什么

社区作者 infosecmonkey 10 月 13 日发布、10 月 20 日更新的 Windows 事件速查指南：讲清关键日志通道（Security、System、PowerShell/Operational、任务计划、远程桌面、WMI…

现代 Windows（Vista 及之后）用二进制 EVTX 格式写事件，每个日志通道是 C:\Windows\System32\winevt\Logs\ 下的独立文件；取证时收集的是这些文件。关键通道：Security（登录、提权、账户变更、进程创建）、System（服务安装 7045、日志清除 104）、Application、PowerShell/Operational（脚本块 4104、模块 4103）、Windows PowerShell（引擎启停 400/403）、TaskScheduler/Operational、TerminalServices（RDP）、WMI-Activity/Operational（WMI 持久化 5861）、Windows Defender/Operational（检出 1116/1117、防护被关 5001）、Sysmon/Operational（进程、网络、注册表、DNS、文件遥测，需部署）。Security 日志用审计关键字而非级别，所以失败登录也显示为'信息'。关键技巧：每条 4624 都有 TargetLogonId，同一会话产生的 4672、4688、4663、4698 会带相同的 SubjectLogonId，4634 登出带相同的 TargetLogonId——按一个 Logon ID 过滤就能还原整个会话。先决条件：最常见的取证结论是'那项没记日志'，出事前先配好。用 auditpol 打开 14 个高级审计子类（凭据验证、Kerberos、登录/注销、特殊登录、账户管理、安全组管理、进程创建等）；给 4688 开命令行记录（组策略：审计进程创建—在进程创建事件中包含命令行）；开 PowerShell 脚本块日志；Security 日志默认 20MB，调大并转发到 SIEM 或事件转发收集器。认证事件：4624 成功登录（看登录类型、IP、工作站名）、4625 失败（SubStatus 说明原因；同一 IP 爆发即喷洒或爆破）、4634/4647 登出、4648 显式凭据登录（runas、PsExec -u）、4672 特权会话、4778/4779 会话重连/断开。登录类型：2 本地交互、3 网络（SMB/映射盘/PsExec/WMI，横向移动主力）、4 批处理、5 服务、7 解锁、8 明文网络、9 新凭据（哈希传递工具痕迹）、10 RDP、11 离线域登录。4625 SubStatus：0xC0000064 用户名不存在（枚举/喷洒）、0xC000006A 密码错（爆破）、0xC0000234 锁定、0xC0000072 已禁用（离职账户）、0xC000006F 非允许时段、0xC0000070 工作站限制、0xC0000193 账户过期、0xC0000133 时钟偏差、0xC000015B 登录类型被拒。可疑 RDP 的样子：外部源 IP、类型 10、同一 Logon ID 上紧跟 4672。Kerberos/NTLM：域控上有全量认证记录，4768 TGT 请求、4769 服务票据（服务账户大量 RC4 票据即 Kerberoasting）、4771 预认证失败、4776 NTLM 验证（该走 Kerberos 的地方出现 NTLM 可能是哈希传递）。账户与组：4720 建账户、4722 启用、4724 他人重置密码、4726 删除、4738 变更、4740 锁定、4728/4732/4756 加特权组——低量高信号，适合做告警。进程执行：4688（看父子关系：winword 拉起 powershell、w3wp 拉起 cmd 都值得细看；-enc、IEX、DownloadString、certutil -urlcache 是经典痕迹）。持久化：7045/4697 服务安装（看 ImagePath 而非显示名；跑在 AppData/Temp 下的服务极可疑）、4698/4699/4702 计划任务、5861 WMI 永久事件消费者。横向移动：源端 RDPClient 1024 加 4648，目的端 1149、4624 type 10、LocalSessionManager 21/22；PsExec 落点典型序列：4624 type 3、4672、5140（ADMIN$）、5145 写 PSEXESVC.exe、7045 装服务、4688。PowerShell：4104 记录去混淆后的脚本内容；即使没开脚本块日志，PowerShell 5 也会自动以 Warning 级记可疑脚本块——在没加固的主机上按 Level 3 筛 4104 是捷径；400 事件里 EngineVersion=2.0 多半是有人用 powershell -version 2 躲日志。反取证：1102（安全日志被清，记下清日志的账户）、104、4719（审计策略被改）、4616（时间被改）、5001（Defender 实时防护被关）、5007（加排除路径）。Sysmon 是倍增器：1 进程创建（哈希、父命令行）、3 网络连接、7 镜像加载（DLL 劫持）、8 远程线程注入、10 读 lsass（凭证转储）、11 文件创建、12/13/14 注册表、22 DNS、25 进程篡改；用维护中的配置部署。分诊四步：1）wevtutil epl 导出全部关键通道并算哈希；2）Get-WinEvent 按哈希表筛（如 24 小时内 4625 按源 IP 分组）；3）离线 EVTX 用 XPath 查（如登录类型 10 的 4624）；4）多主机用 Hayabusa/Chainsaw/EvtxECmd 做时间线。排查剧本：爆破到妥协（同一 IP 大量 4625 0xC000006A、同一 IP 同账户 4624、同一 Logon ID 4672、4688 看先跑了什么）、RDP 横向、恶意服务/计划任务（装完后出现 1102/104 说明对方在清痕迹）。验证：先在实验室造几个良性事件确认基线真能产出事件。常见坑：4688 有但命令行空等于没开命令行策略；auditpol 显示开了但没日志等于旧版基础审计策略在 GPO 里覆盖了高级子类；Security 日志只覆盖几小时等于默认 20MB 太小；跨主机时间对不上是因为 EVTX 存 UTC、查看器按本机时区显示，统一转 UTC。25 个必记事件 ID：4624/4625、4634/4647、4648、4672、4688、4697、4698、4719、4720、4724、4728/4732/4756、4740、4768/4769、4771、4776、5140/5145、1102、104、7045、1149、21/24/25、4104、5861、1116/5001。

Windows Event IDs for Forensic Investigations. How Windows Event Logging Works: Modern Windows (Vista and later) writes events in the binary EVTX format. Each log channel is a separate file under C:\Windows\System32\winevt\Logs\. When you collect evidence, you collect these files, not screenshots of Event Viewer. Key channels: Security (Security.evtx - logons, privilege use, account changes, process creation, object access), System (System.evtx - service installs 7045, log clears 104, driver loads, shutdowns), Application (app crashes, installer activity), PowerShell/Operational (script block 4104 and module 4103 logging), Windows PowerShell (legacy engine start/stop 400/403, pipeline 800), TaskScheduler/Operational, TerminalServices RCM/LSM (RDP connections), WMI-Activity/Operational (WMI event subscription persistence 5861), Windows Defender/Operational (detections 1116/1117, protection disabled 5001), Sysmon/Operational (process, network, registry, DNS, file telemetry if deployed). Event Types: the Security log uses audit keywords rather than levels, which is why every Security event shows level "Information" even for a failed logon. Pivot on the Logon ID: every 4624 records a TargetLogonId; the same value appears as SubjectLogonId on 4672, 4688, 4663, 4698 generated inside that session, and as TargetLogonId on the matching 4634 logoff. Filtering on one Logon ID reconstructs everything a session did. Prerequisites: the most common finding is "that was not logged" - fix it before the incident. Enable Advanced Audit Policy subcategories (Credential Validation, Kerberos Authentication Service, Kerberos Service Ticket Operations, Logon/Logoff, Special Logon, User Account Management, Security Group Management, Process Creation, Security System Extension, Other Object Access Events, Detailed File Share, Audit Policy Change, Security State Change) via auditpol; include command line in 4688 via GPO (Audit Process Creation > Include command line in process creation events); enable PowerShell Script Block Logging; raise the Security log from the 20 MB default and forward to a SIEM or WEF collector. Authentication events: 4624 successful logon (check LogonType, IpAddress, WorkstationName), 4625 failed logon (Status/SubStatus explain why; burst from one IP means spray or brute force), 4634 logoff, 4647 user-initiated logoff, 4648 logon with explicit credentials (runas, PsExec -u), 4672 special privileges assigned (admin-equivalent session), 4778/4779 session reconnected/disconnected. Logon types: 2 Interactive, 3 Network (SMB, mapped drive, PsExec, WMI - lateral movement workhorse), 4 Batch, 5 Service, 7 Unlock, 8 NetworkCleartext, 9 NewCredentials (runas /netonly), 10 RemoteInteractive (RDP), 11 CachedInteractive, 12 CachedRemoteInteractive, 13 CachedUnlock. 4625 SubStatus codes: 0xC0000064 user name does not exist (enumeration/spraying), 0xC000006A correct user wrong password (brute force), 0xC0000234 account locked out, 0xC0000072 account disabled, 0xC000006F outside logon hours, 0xC0000070 workstation restriction, 0xC0000071 password expired, 0xC0000193 account expired, 0xC0000133 clock skew, 0xC000015B logon type not granted. A suspicious RDP logon: external source address, type 10, and an immediate 4672 on the same Logon ID. Kerberos and NTLM: on a domain, the DC holds the authentication record - 4768 Kerberos TGT requested, 4769 service ticket requested (many RC4 requests for service accounts suggests Kerberoasting), 4770 renewed, 4771 pre-auth failed, 4776 NTLM credential validation. Account and group management: 4720 created, 4722 enabled, 4723 own password changed, 4724 password reset by another, 4725 disabled, 4726 deleted, 4738 changed, 4740 locked out, 4728/4732/4756 added to privileged groups - high signal, low volume, ideal alerts. Process execution: 4688 process created (parent/child: winword.exe spawning powershell.exe, w3wp.exe spawning cmd.exe; -enc, IEX, DownloadString, certutil -urlcache are classic indicators), 4689 exited, Sysmon 1. Persistence: 7045/4697 service installed (judge ImagePath not display name; services from AppData/Temp/Users/Public are suspicious), 4698/4699/4702 scheduled tasks, 5861 WMI permanent event consumer. Lateral movement: source RDPClient 1024 + 4648; destination 1149, 4624 type 10, LocalSessionManager 21/22; PsExec pivot on destination: 4624 type 3, 4672, 5140 (ADMIN$), 5145 writing PSEXESVC.exe, 7045 installing service, 4688. PowerShell: 4104 script block logged (deobfuscated content), 4103 module logging, 400/403 engine started/stopped (EngineVersion=2.0 means dodge attempt), 800 pipeline details; unhardened hosts auto-log suspicious 4104 at Warning. Defense evasion: 1102 security log cleared (records the account), 104 log cleared, 4719 audit policy changed, 4616 system time changed, 5001 real-time protection disabled, 5007 Defender config changed, 1116/1117 detection/action, 4657 registry modified. Sysmon: 1 process create, 3 network connection, 7 image loaded, 8 CreateRemoteThread, 10 ProcessAccess (lsass handle = credential dumping), 11 FileCreate, 12/13/14 registry, 22 DNS query, 23/26 file delete, 25 process tampering. Collection workflow: wevtutil epl export with hashes; Get-WinEvent hashtable filters; offline EVTX XPath queries; Hayabusa/Chainsaw/EvtxECmd timelines. Investigation playbooks for brute force, RDP lateral movement, malicious service/task. Verification: generate benign test events in a lab first. Gotchas: 4688 without command line (policy not applied), legacy audit policy overriding subcategories, 20 MB default retention, UTC vs local timestamps, dash in 4625 IpAddress. 25 Event IDs to know cold: 4624, 4625, 4634/4647, 4648, 4672, 4688, 4697, 4698, 4719, 4720, 4724, 4728/4732/4756, 4740, 4768/4769, 4771, 4776, 5140/5145, 1102, 104, 7045, 1149, 21/24/25, 4104, 5861, 1116/5001.

推荐理由

与终端故障排查、异常登录核查工作有关。值得带走三个：一是 Logon ID 关联思路——按一个 Logon ID 过滤还原整个会话；二是 4625 SubStatus 速查（0xC0000064 用户名枚举、0xC000006A 密码爆破）；三是'先配基线再出事'的原则（审计策略、日志大小、异地转发）。适用条件：需要排查 Windows 异常登录、可疑进程或服务安装的场景；动手部分以理解方法为主，不强制实验。
