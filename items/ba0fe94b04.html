攻击者入侵了微软官方的 Agent Framework Python 包，在 PyPI 上发布了两个恶意版本，意图窃取开发者系统中的云凭证与其他敏感信息。Microsoft Agent Framework 是微软用于构建 AI 智能体并在工作流中协调它们的开源工具包，在 PyPI 上月下载量约 20 万次。恶意版本 1.26.1 与 1.26.2 于 11 月 17 日发布，其中的凭证窃取程序会在受影响环境的正常 Python 启动过程中自动执行，即使没有导入 Agent Framework 包也会运行。两个版本都保留了对合法 agent-framework-core 1.26.0 包的依赖，使框架正常工作，恶意软件则在后台运行。多家安全厂商发现并记录了这次攻击，包括 Socket、Step Security 与 Ox Security。1.26.1 版的窃取程序从环境变量、本地配置文件以及权限允许范围内的其他运行进程中收集机密，目标包括 Azure、AWS、GitHub、Docker、Hugging Face、OpenAI 等服务的凭证；还会尝试获取 Azure 托管身份访问令牌与 Azure DevOps OIDC 令牌，可能让攻击者进一步访问云资源。1.26.2 版增加了 GitHub Actions OIDC 令牌请求，并搜索 GitHub runner 目录。据 Socket 与 StepSecurity，第一版利用 agent_framework_meta.pth 在 Python 启动时执行 agent_framework_meta/_telemetry.py 中的窃取程序；第二版恢复了原始包初始化文件，把恶意代码移入 af_runtime_diag.pth 与 af_runtime_diag.py。两个版本都把收集的数据外发到同一攻击者控制的端点。PyPI 隔离了第一个恶意版本，但攻击者约 2.5 分钟后又发布了第二个版本，该版本也在约 8 分钟后被隔离；第二版的出现说明攻击者在首次隔离后仍持有发布权限。攻击者如何获得以微软官方 PyPI 项目名义发布恶意版本的权限，目前尚不清楚；BleepingComputer 已联系微软，截至发稿时未收到回应。安装过任一恶意版本的开发者应隔离受影响环境，在确保安全前避免运行 Python 或 pip，并用安全的 1.26.0 版本从已知干净的环境重建；所有可能已暴露的凭证都应立即轮换。调查时应在出站日志中查找上述 webhook 地址，区分被拦截的请求与已完成的传输，以确定实际泄露程度。

原文

Hackers compromised Microsoft's official Agent Framework Python package on PyPI, publishing two malicious versions designed to steal cloud credentials and other sensitive information from developers' systems. Microsoft Agent Framework is Microsoft's open-source toolkit for building AI agents and coordinating them in workflows. It's a fairly popular tool with roughly 200,000 monthly downloads on PyPI. The malicious releases, versions 1.26.1 and 1.26.2, were published on November 17, 2026, and contained a credential stealer that executed automatically during normal Python startup in affected environments, even when the Agent Framework package was not imported. Both versions retained their dependency on the legitimate `agent-framework-core` 1.26.0 package, allowing the framework to function normally while the malware ran in the background. Multiple security firms discovered and documented the attack, including Socket, Step Security, and Ox Security. Version 1.26.1 contained a credential stealer that harvested secrets from environment variables, local configuration files, and other running processes where permissions allowed, targeting Azure, AWS, GitHub, Docker, Hugging Face, OpenAI, and other services. The malware also attempted to obtain Azure managed identity access tokens and Azure DevOps OIDC tokens, potentially giving attackers access to additional cloud resources. Version 1.26.2 added GitHub Actions OIDC token requests and searches of GitHub runner directories. According to Socket and StepSecurity, the first malicious release used `agent_framework_meta.pth` to execute the credential stealer in `agent_framework_meta/_telemetry.py` during Python startup. The second release restored the original package initializer and moved the malicious code into `af_runtime_diag.pth` and `af_runtime_diag.py`. Both versions exfiltrated collected data to the same attacker-controlled endpoint, `https://webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb`. PyPI quarantined the first malicious release, but the attacker published a second version roughly 2.5 minutes later, which was also quarantined about eight minutes afterward. The second release indicates that the attacker still had publishing access after the initial quarantine. It remains unclear how the attacker gained access to publish malicious releases under Microsoft's official PyPI project. BleepingComputer has contacted Microsoft to learn what the point of breach was, but we have not received a response by publication time. Developers who installed either malicious version should isolate affected environments, avoid running Python or pip until they are secured, and rebuild from a known-clean environment using the safe 1.26.0 release. Any potentially exposed credentials that were within the reach of the compromised environment should be rotated immediately. To determine the exact level of compromise, investigators should look for the specific webhook URL path in egress logs and distinguish blocked requests from completed transfers.
