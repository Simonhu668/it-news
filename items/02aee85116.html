2026 年 10 月 13 日，SAP 发布安全更新，修复 CVE-2026-89107——SAP S/4HANA“管理替换/验证规则”（Manage Substitution/Validation Rules）功能中的严重代码注入漏洞。已认证且具备特定业务权限的攻击者可执行任意 ABAP 代码。漏洞 CVSS 3.1 评分 9.9（严重），为网络攻击向量、低复杂度、需低权限、无需用户交互，可导致机密性、完整性、可用性完全丧失。

漏洞原理（CWE-94）：财务与控制模块用户用领域脚本语言定义业务规则（如某凭证记到哪个总账科目），但 SAP 对规则定义功能处理的输入校验不足。特制输入可逃出脚本语言，被规则引擎当作可执行 ABAP 代码解析——从“写一条财务规则”的业务权限直接跨越到应用服务器代码执行，中间没有任何二次授权检查。攻击者初始凭证可来自钓鱼的财务人员、被攻陷的服务账户或内部低权限人员。

受影响版本：所有开放“管理替换/验证规则”Fiori 应用的 S/4HANA 系统（财务凭证替换/验证规则的现代继任者，对应经典 GGB1/OB28/OBBH 事务码）。SAP 已在 2026 年 10 月安全补丁日修复，管理员需查阅当日 SAP Security Notes 确认确切版本映射。

利用现状：写作时未确认公开 PoC，未列入 CISA KEV 目录。但作者警告，高价值 ERP 漏洞常先被静默武器化再出现公开 PoC，缺席公开利用应视为补丁窗口期而非安全证明。

缓解措施：立即打上 2026 年 10 月 SAP Security Note 补丁（开发、测试、生产全覆盖，关单前让 Basis 团队核实补丁级别）；审计哪些用户/角色能访问规则管理应用及经典事务码，收回非必要授权——对该 CVE 而言，身份与权限治理是与补丁并列的关键防线；将每条替换/验证规则视为可能被篡改，请职能顾问复核近期新建或修改的规则；检查应用日志、ST22 短转储、SM21 系统日志中规则变更前后的异常；职责分离：同一用户不能既定义财务规则又过账受其影响的凭证。

原文

On October 13, 2026, SAP published security updates for CVE-2026-89107, a critical code-injection vulnerability in SAP S/4HANA (Manage Substitution/Validation Rules) that lets an authenticated attacker with specific business privileges execute arbitrary ABAP code. The flaw carries a CVSS 3.1 score of 9.9 (Critical) — network attack vector, low complexity, low privileges required, no user interaction; total loss of confidentiality, integrity, and availability.

The vulnerability is deceptively simple (CWE-94). The rule-definition functionality lets finance users define business rules using a domain-specific scripting language, but SAP's disclosure states this functionality does not sufficiently validate the input it processes. Crafted input escapes the scripting language and is interpreted as executable ABAP code by the rule-processing logic — the attack starts with business-level privileges (defining a finance rule) and lands at code execution on the application server, with no extra authorization check between "write a rule" and "run my code," because the rule engine itself is the confused deputy.

Affected versions: SAP S/4HANA systems with the Manage Substitution/Validation Rules functionality — the Fiori-based apps used to create substitution and validation rules for financial documents (the modern successors to classic GGB1/OB28/OBBH customizing transactions in FI). SAP addressed the flaw in its October 2026 Security Patch Day; administrators should consult that day's SAP Security Notes for the exact note and product-version mapping.

Exploitation status: no confirmed public proof-of-concept at the time of writing, and the flaw is not in the CISA Known Exploited Vulnerabilities catalog. But authenticated code-injection bugs in widely deployed ERP platforms are exactly the kind of weakness that gets weaponized quietly — treat the absence of public exploitation as a head start for patching, not evidence of safety.

Mitigation: patch immediately — apply the SAP Security Note from the October 2026 Security Patch Day across all S/4HANA systems (development, QA, and production); restrict rule-definition access by auditing which users and roles can reach the Manage Substitution/Validation Rules apps and removing the authorization from anyone who doesn't need it (identity access management is a first-line control for this CVE); treat every substitution and validation rule as potentially tampered with and have a functional consultant review recently created or modified rules; monitor application logs, ST22 short dumps, and SM21 system logs around rule changes; enforce segregation of duties so the same user cannot both define financial rules and post the documents those rules affect.
