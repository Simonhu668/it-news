正文 · AI 翻译

微软在 2026 年 10 月的补丁星期二更新中修复了 CVE-2026-103572，这是 Visual Studio Copilot 中的一个 Important 级远程代码执行漏洞，CVSS 评分为 8.8。安全研究员 Johann Rehberger 公开了该漏洞的技术细节与概念验证演示。该漏洞同时影响 Visual Studio 与 SQL Server Management Studio（SSMS）。

漏洞位于两者共用的动态链接库 Microsoft.VisualStudio.Copilot.Core.dll。正常情况下，应用会阻止 AI 助手在未经用户确认时修改敏感配置文件，代码通过比对目标文件名与 .mcp.json 或 settings.visualstudio.json 等受保护名称来执行检查。但 Windows 文件 API 在写入操作时会忽略文件名末尾的句点，带尾随句点的文件名因此通过了字符串比对检查，随后 Win32 层去掉句点，实际写入了受保护的配置文件。

攻击者通过间接提示注入触发该问题：当 AI 助手处理不可信文件或外部数据时，攻击者可诱导其修改本地配置。在 Visual Studio 与 SSMS 中，被劫持的助手可将恶意命令注册为模型上下文协议（MCP）服务器，IDE 随后自动启动该服务器并执行命令；在 Visual Studio 中，助手还可把内部搜索配置 ripgrepPath 指向任意可执行文件，助手每次执行文本搜索时都会启动该文件。

受影响的产品包括带 GitHub Copilot 集成的 Visual Studio 2026、Visual Studio 2022 与 Visual Studio Tools for Applications，以及带 Copilot 与 MCP 支持的 SQL Server Management Studio。Rehberger 于 2026 年 8 月 4 日向微软报告该漏洞，微软于 2026 年 10 月 13 日发布官方安全补丁，修复方式是在文件名检查前调用 GetFullPath，先去掉尾随句点并解析相对路径成分。修复版本为 Visual Studio 2022 17.14.42 与 Visual Studio 2026 18.10.4。微软确认目前没有在野利用，但公开的概念验证演示已经出现。管理员与开发者应尽快应用 2026 年 10 月的 Visual Studio 与 SSMS 安全更新，并在补丁完成前限制 AI 助手处理不可信仓库或未经验证的 MCP 服务器响应。

原文

Microsoft released an October Patch Tuesday update to fix CVE-2026-103572, an Important remote code execution flaw in Visual Studio Copilot. Furthermore, security researcher Johann Rehberger publicly disclosed the technical details and proof-of-concept exploit demonstrations for this Visual Studio Copilot RCE bug. The vulnerability carries a CVSS score of 8.8 and affects both Visual Studio and SQL Server Management Studio (SSMS).

Microsoft's official CVE-2026-103572 security advisory warns that attackers can exploit this flaw to run arbitrary commands. Because SQL Server Management Studio shares core code with Visual Studio, a single faulty library exposes both tools.

Specifically, the flaw resides in a shared dynamic link library named Microsoft.VisualStudio.Copilot.Core.dll. An attacker can trigger the Visual Studio Copilot RCE through indirect prompt injection when the AI assistant processes untrusted files or external data. Although public proof-of-concept demonstrations now exist online, Microsoft has confirmed no active exploitation in the wild so far.

In his technical analysis, Johann Rehberger explained the underlying file validation error. Normally, the application blocks the AI agent from modifying sensitive configuration files without user confirmation. In particular, the code checks whether a target file name matches protected names like .mcp.json or settings.visualstudio.json.

However, Windows file APIs ignore trailing periods at the end of file names during write operations. Consequently, an input string with a trailing dot passes the security check because the text strings do not match. Afterward, the Win32 layer strips the trailing dot and overwrites the actual protected configuration file.

Once an attacker hijacks the AI assistant via untrusted content, the agent can alter local configuration settings. First, in both Visual Studio and SSMS, the compromised agent can register a malicious command as a Model Context Protocol (MCP) server. The IDE then launches that rogue MCP server automatically and executes the command. Second, Visual Studio users face an additional attack vector through the internal search configuration. Specifically, the hijacked agent can point the ripgrepPath setting to an arbitrary executable binary. Whenever the AI assistant runs a text search, Visual Studio launches that binary on the host machine.

Rehberger reported the vulnerability to Microsoft on August 4, 2026. Subsequently, Microsoft shipped the official security patch on October 13, 2026. To fix the flaw, Microsoft added a GetFullPath function call before the file name check. As a result, the application removes trailing dots and resolves relative path components before validating file access. Administrators and developers should apply the October 2026 security updates for Visual Studio and SSMS right away, and restrict AI agents from processing untrusted repositories or unverified MCP server responses until patching is complete.
