微软近期发布速度很快。有些确实有用，例如 Agent 365 对无主智能体的可见性；有些则会给 IT 团队带来实际工作，例如判断哪些 Power Apps 现在应向 Copilot 开放、由谁决定。第一，智能体数量已多到无法人工治理。一家大型组织启用微软新的 Agent 365 治理工具后，发现环境中已有 72,000 个智能体在运行，无人清点过，大多数无人认领；每周还在新增 4,000 至 5,000 个。微软自身数据显示，超 80% 的组织已在运行智能体，仅约 10% 有治理计划。这与 Teams 或 SharePoint 早期如出一辙：创建容易、治理滞后，IT 团队花数年收拾残局；智能体走的是同一条路，只是更快。Agent 365 是微软基于 Entra、Defender、Purview 与 Intune 构建的治理层，提供租户内全部智能体的中央登记：归属、访问数据与工具连接数量。新内容有两项：智能体成本管理——管理员可设置月度支出硬上限、每用户限额与部门级 Azure 费用分摊，Viva Insights 仪表板让业务与财务负责人无需进入管理中心即可看到支出情况，微软的提法是像管理费用一样管理智能体；第三方智能体登记——Registry Sync 现可同步 Salesforce AgentForce、AWS、Google Cloud 等微软以外工具的智能体，清单不再限于 Copilot Studio 构建的智能体。建议先做审计：尚未启用的先启用 Agent 365，看清租户内实际运行的内容并建立归属模型，再考虑成本归属，因为财务团队迟早会问起智能体支出。第二，智能体已经跑出租户之外。员工运行 AI 智能体无需 IT 批准：GitHub Copilot CLI、Claude Code 等开发者工具可经 npm、pip 或 VS Code 市场安装，无需管理员权限；OpenClaw、Claude Desktop 等消费级应用像普通应用一样安装；IT 往往事后才从 Defender 扫描中得知。约 29% 的员工已在设备上本地运行未授权智能体；由于这些工具在设备本地运行，完全绕过云端检查点。新内容是：Agent 365 可通过 Defender 与 Intune 持续扫描托管设备上的 GitHub Copilot、OpenClaw 等本地智能体平台，把它们与受管工具一同纳入登记，并通过自动生成的 Intune 策略拦截不需要的平台。建议把影子 AI 发现加入下一轮安全评审；问题不在于员工是否在使用未授权 AI 工具，而在于是否看得见用的是哪些、发现后按什么政策处理。已使用 Defender 与 Intune 的组织，基础设施已有，只须配置。第三，智能体现在可以操作多年来构建的全部应用。Power Apps 中存有真实业务数据：表、窗体、网格与为特定流程定制的控件，过去与 AI 是分开的。微软新推 App MCP 开关：为任一现有 Power App 开启后，该应用的表、窗体、网格与自定义控件即向 Copilot 开放，Copilot 可读可写，无需重建。例如用户现在可直接在 Outlook 中一步完成会议与工时的核对。微软内部运行的 Power Apps 超 80 万个，多数组织也有成百上千个，现有工作无需重头开始即可接入 AI。建议先盘点现有 Power Apps，决定哪些应向 Copilot 开放、哪些不应；优先支持高价值重复性工作的应用，但在启用 App MCP 前先复核权限、数据敏感度与归属。这不应由制作者逐个决定，而应作为受管能力，配有明确的审批、监控与回滚流程。智能体很有用；租户内、用户笔记本上、Power Apps 里的智能体无论有无治理计划都会继续增多。多数 IT 团队仍把智能体当作实验问题，而真正的问题是运行控制；当前优先事项是可见性：建立一份关于智能体、工具、负责人、数据访问与成本的可靠清单。

原文

Microsoft has been shipping fast. Some of what released recently is genuinely useful, such as Agent 365's visibility into ownerless agents, for example. Other releases are going to create real work for IT teams, like figuring out which of your Power Apps should now be exposed to Copilot and who gets to decide that. 1. Agents are now too numerous to govern manually. When one large organization turned on Microsoft's new Agent 365 governance tooling, they discovered 72,000 agents already running in their environment. Nobody had counted them. Nobody owned most of them. They are now adding 4,000 to 5,000 new agents every week. Microsoft's own data shows that more than 80% of organizations are already running agents and only about 10% have any governance plan in place for them. Think back to the early days of Teams or SharePoint. Creation was easy, governance lagged behind, and IT teams spent years cleaning up the mess. Agents are following the same pattern, just faster. Manual oversight at that scale is not realistic. Agent 365 is Microsoft's governance layer built on Entra, Defender, Purview, and Intune. It gives admins a central registry of every agent running in the tenant: who owns each one, what data it is accessing, and how many tool connections it has. What is new with Agent 365: Agent cost management. Admins can now set hard monthly spending caps, per-user limits, and department-level Azure chargebacks. Viva Insights dashboards bring spending visibility to business and finance leaders without needing access to the M365 admin center. Microsoft's framing: manage agents like expenses, with managers approving agent spend the same way they approve a budget line. Third-party agent registry. Registry Sync now pulls in agents from outside Microsoft's own tools such as Salesforce AgentForce, AWS, and Google Cloud. In other words, the agent inventory is no longer limited to what was built in Copilot Studio. What to do: run the audit first. Turn on Agent 365 if you have not, see what is actually running in your tenant, and establish an ownership model. Then think about cost accountability, because finance teams are going to start asking questions about agent spend and IT should have the answers ready. 2. Agents have escaped the tenant. Employees do not need IT approval to run an AI agent. Developer tools like GitHub Copilot CLI or Claude Code install via npm, pip, or the VS Code Marketplace, with no admin rights needed. Consumer apps like OpenClaw or Claude Desktop install like any regular app. IT only finds out after the fact, when Defender scans the device. About 29% of employees are already running unsanctioned AI agents locally on their devices. Because these tools run locally on the device, they bypass cloud-based checkpoints entirely. What is new: through Defender and Intune, Agent 365 can now continuously scan managed devices for local agent platforms like GitHub Copilot and OpenClaw, surface them in the same registry as sanctioned tools, and block the ones you do not want via an automatically generated Intune policy. What to do: add shadow AI discovery to your next security review cycle. The question is not whether employees are using unauthorized AI tools. They are. The question is whether you have visibility into which ones, and whether you have a policy for what happens when you find them. If your organization already uses Defender and Intune, the infrastructure is there. It just needs to be configured. 3. Agents can now act on every app you have ever built. Have you been building Power Apps over the years? Those apps hold real business data, like tables, forms, grids, custom controls built for specific workflows. Until now, they stayed separate from AI. Microsoft shipped a new 'App MCP' toggle. Switch it on for any existing Power App, and that app, its tables, forms, grids, and custom controls, becomes accessible to Copilot. Copilot can read from it and write to it. No rebuilding required. For example, a user can now reconcile their meetings with their timesheet in one step, directly from Outlook. Microsoft has over 800,000 Power Apps running internally. Most organizations have hundreds or thousands of their own. All of that existing work can now be connected to AI without starting over. What to do: start an inventory of your existing Power Apps and decide which ones should be exposed to Copilot, and which ones should not. Prioritize apps that support high-value, repetitive work, but review permissions, data sensitivity, and ownership before enabling App MCP. This should not be a maker-by-maker decision. Treat it as a governed capability with clear approval, monitoring, and rollback processes. Agents are useful. The ones running in your tenant, on your users' laptops, and inside your Power Apps are going to keep multiplying whether you have a governance plan or not. Most IT teams are still treating agents as an experimentation problem, while the real issue is operational control. The priority now should be visibility: build one reliable inventory of the agents, tools, owners, data access, and costs in your environment.
