PolinRider 供应链攻击波及 7600 多个 GitHub 仓库：伪造提交植入加载器，构建时即触发

官方依据：SafeDep 本周发布的报告，经 The Hacker News 2026 年 11 月 27 日报道；Apiiro 2026 年 11 月 9 日的统计｜适用产品及版本：托管在 GitHub 上的开源项目与使用其代码的组织，涉…

thehackernews·媒体报道安全与运维行业视野收录 11-27 18:30

正文 · AI 翻译

代号为 PolinRider 的攻击活动被发现向 GitHub 仓库植入 Python 加载器，有证据表明该活动最早可追溯到 2025 年 2 月。

“加载器藏在一个小的 utils 包或 conftest.py 文件中，”SafeDep 在本周发布的报告中表示。“当 Python 导入该文件时，加载器读取某个以太坊钱包向自身发送的最新一笔交易，将交易输入数据解码为 JavaScript，再用 Node.js 执行。”

随后 JavaScript 代码读取第二个钱包以定位命令与控制（C2）服务器，并通过 node -i 进程把下一阶段交给一个分离的交互式 Node.js 环境。

这家软件供应链安全公司表示，已在属于 260 个账号的 375 个公开仓库中发现该加载器。目前没有证据表明加载器通过 PyPI 或 npm 分发。

PolinRider 是被归因于朝鲜威胁行为者的恶意活动的名称。近期报告显示，该活动通过多种渠道分发恶意软件，包括：利用钓鱼邮件与 BlockNovas、AccuraSoftHire（accurasofthire[.]com）、HuntRole（huntrole[.]org）等虚假招聘门户的欺诈招聘活动，诱使求职者以完成带回家的评估为名运行夹带恶意软件的项目；通过劫持维护者账号，在开源生态中发布恶意包，以虚假字体文件、Visual Studio Code（VS Code）自动运行任务与 Git 历史重写植入经过混淆的恶意软件；利用已被入侵的开发者机器窃取 GitHub 令牌，向其有权限的开源仓库强制推送恶意提交。

PolinRider 加载器取回加密的第二阶段 Node.js 有效载荷，扫描受感染主机上已安装的开发者应用（如 GitHub Desktop、Cursor、VS Code 与 Google Antigravity），篡改最常用的工具以执行攻击者控制的代码并投递信息窃取恶意软件。

PolinRider 被评估为与长期活动 Contagious Interview 并行运行的子集群：后者以社会工程入侵开发者系统，PolinRider 则滥用已获得的访问权限修改仓库，把它们变成恶意软件分发渠道。

Palo Alto Networks Unit 42 在上月发布的报告中表示，网络犯罪团伙部署供应链蠕虫是为了伺机窃取，而朝鲜国家支持的威胁行为者把开源软件注册库作为针对企业环境的主要初始访问向量；入侵单个维护者账号或注册库范围，就能把开源依赖变成波及广泛的受影响云环境。

JavaScript 恶意软件按以下步骤执行：读取某个以太坊钱包的最新交易；用被称为 NullReceiver 的技术，从目标钱包地址前 8 个字节两次提取 C2 服务器地址（103.179.142[.]155），而最后 12 个字节代表 ASCII 字符串“helloipbot!!”；用该 IP 地址通过 443 端口获取两个有效载荷“0x/cls”与“0x/ls”。

SafeDep 的最新发现显示，这些仓库被注入了一个 58 行的 Python 加载器，它从一个以太坊钱包提取 JavaScript 代码，再联系第二个钱包解析出 C2 服务器（95.135.181[.]84）。NullReceiver 技术的一个决定性特征是，人为构造的目标钱包地址中包含标记“68656c6c6f6970626f742121”，它始终转译为“helloipbot!!”。

“/0x/cls 脚本运行两次，一次在当前进程中用 eval 执行，一次在新进程中执行，”SafeDep 表示。“/0x/ls 脚本只在新进程中运行。”这些有效载荷的确切性质仍不清楚。不过，此前的攻击波次被观察到安装窃取器，窃取环境机密、浏览器密码、Cookie 与钱包数据。值得注意的是，同一钱包地址已在其他攻击波次中被重复使用，包括推送合法 npm 包的受损版本、HuntRole 虚假招聘活动，以及使用名为 Eternity0207 的 GitHub 账号向 AsyncAPI Generator、CircuitVerse 与 Open Food Facts 等开源项目提交 200 多个拉取请求，随后强制推送包含经过混淆的加载器的修改提交。

AsyncAPI Generator 的一位维护者称，每次有效载荷在分支上停留 30 至 40 分钟后又被强制推送走，最终差异看起来是干净的。加载器在开发者运行“npm run build”（AsyncAPI Generator）、加载测试配置（Open Food Facts）或在 VS Code 中打开文件夹（CircuitVerse）时执行。该 GitHub 账号已被封停。

Apiiro 估计，PolinRider 已在至少 7,609 个 GitHub 仓库中被发现，这些仓库属于 2,330 个账号，其中大多数属于开发者。受害者包括 Neutralinojs、InstaWP Connect 与 fxhash。2026 年 10 月 27 日至 11 月 6 日期间，加载器被推送到 2,040 个仓库。

“该蠕虫利用窃取的 GitHub 访问权限重写开发者已经提交的提交，保留作者、信息与日期，并在构建配置中数百个空格之后添加加载器，”Apiiro 研究员 Shmulik Cohen 表示。“构建项目时它就会运行。在最新一波攻击中，在 VS Code 中打开文件夹就足够了。加载器从以太坊钱包读取它的服务器，因此拿掉一台服务器毫无作用：一笔交易就能把每个加载器转移到下一个服务器。”

这一进展出现之际，OpenSourceMalware 表示发现了一起 2025 年 5 月的 PolinRider 攻击，比最早有记录的受害者早了 8 个月。该攻击针对 9 个包，在 90 分钟内利用被劫持的维护者账号推送了投毒版本：itsa-utils@1.4.2、itsa-jsext@2.0.3、itsa-react-docviewer@16.1.2、itsa-cli@16.5.3、itsa-react-button@16.0.11、itsa-react-maskedinput@16.1.2、itsa-react-checkbox@16.0.5、itsa-react-focuscontainer@16.0.10、itsa-react-input@16.1.2。这些包均被发现利用 EtherHiding（NullReceiver 的前身）取回名为 JADESNOW 的 JavaScript 下载器，进而投递 Contagious Interview 活动中使用的基于 Python 的后门 InvisibleFerret，以及 Socket.IO RAT 与基于 Python 的窃取器。

“2025 年的样本带有 PolinRider 的有效载荷，但没有其有记录的传播行为，”安全研究员 Paul McCarty 与 Jenn Gile 表示。“区块链记录把攻击者活动的源头追溯到 2025 年 2 月。感染可能自 2025 年起一直持续在维护者的机器上，因为 2026 年的推送就是从那台机器发起的。”

原文

The threat actors behind the PolinRider campaign have been observed planting a Python loader in GitHub repositories, as evidence emerges that the activity may have started as far back as February 2025.

"The loader hides in a small utils package or in conftest.py," SafeDep said in a report published this week. "When Python imports the file, the loader reads the newest transaction that an Ethereum wallet sent to itself. It decodes the input data of that transaction as JavaScript and runs it with Node.js."

The JavaScript code, for its part, reads a second wallet to locate the command-and-control (C2) server and then passes the next stage to a detached interactive Node.js environment by means of a node -i process.

The software supply chain security company said it identified the loader in 375 public repositories that belong to 260 accounts. There is no evidence that the loader has been distributed via PyPI or npm.

PolinRider is the name assigned to a malicious campaign linked to North Korean threat actors. Recent reports indicate that the activity employs various channels to distribute malware, including fraudulent recruitment campaigns that make use of phishing emails and fake hiring portals like BlockNovas, AccuraSoftHire ("accurasofthire[.]com"), and HuntRole ("huntrole[.]org") to trick prospective targets into running malware-laced projects under the pretext of a take-home assessment; publishing malicious packages across open-source ecosystems by hijacking maintainer accounts to plant obfuscated malware through fake font files (fa-solid-400.woff2, fa-solid-500.woff2, or fa-solid-300.llf), Visual Studio Code (VS Code) auto-run tasks, and Git history rewriting; and using compromised developer machines to steal their GitHub tokens and force-push malicious commits into open-source repositories they have access to.

At a high level, the PolinRider loader retrieves an encrypted second-stage Node.js payload that scans the infected host for installed developer applications, such as GitHub Desktop, Cursor, VS Code, and Google Antigravity, and tampers with the most frequently used tools to execute attacker-controlled code and deliver infostealer malware.

It's worth noting here that PolinRider is assessed to be a sub-cluster operating in parallel with a long-running campaign codenamed Contagious Interview. While the latter is more of a social-engineering entry point that's used to compromise developer systems, PolinRider abuses the access to modify repositories and turn them into a distribution channel for malware.

"Cybercriminal groups deploy supply chain worms for opportunistic theft. On the other hand, North Korean state-sponsored threat actors use open-source software registries as a primary initial access vector targeting corporate environments," Palo Alto Networks Unit 42 said in a report published last month. "Threat actors demonstrate how compromising a single maintainer account or registry scope converts open-source dependencies, resulting in widespread affected cloud environments."

The JavaScript malware is designed to perform the following steps: read the latest transaction associated with an Ethereum wallet ("0xa322E5f3D311D3080e6f0121063e9aDC2490Ef1a"); get its destination wallet address ("0x67B38e9b67B38E9b68656c6C6f6970626f742121"); extract the C2 server address twice ("103.179.142[.]155") from the first eight bytes ("67B38e9b" and "67B38E9b") of the wallet address, using a technique referred to as NullReceiver, while the last 12 bytes represent the ASCII string "helloipbot!!."; and use the IP address to fetch two payloads, "0x/cls" and "0x/ls," over port 443.

The latest findings from SafeDep show that the repositories are injected with a 58-line Python loader that reads the "0x3b1574417524c11a7403c4b232CAcBb320CceBC6" wallet to extract JavaScript code that then reaches out to a second wallet ("0x1eEf0849EDa15d87f64e51C73C8442Cf3c8bCEF3") to obtain the destination wallet associated with the latest transaction ("0x5F87b5545F87b55468656C6C6f6970626f742121"), which is then used to parse the C2 server ("95.135.181[.]84"). A defining aspect of NullReceiver is the marker "68656c6c6f6970626f742121" in the made-up destination wallet address that consistently translates to "helloipbot!!."

"The /0x/cls script runs twice, once with eval in the current process and once in a new process," SafeDep said. "The /0x/ls script runs only in a new process." The exact nature of these payloads remains unknown. However, prior waves have been observed installing a stealer that harvests environment secrets, browser passwords, cookies, and wallet data. Interestingly, the wallet address "0x1eef0849eda15d87f64e51c73c8442cf3c8bcef3" has been reused by the threat actors across other attack waves: pushing compromised versions of legitimate npm packages such as @adminide-stack/utils, @adminide-stack/health-api-server, @adminide-stack/user-activity-browser, @adminide-stack/forms-core, @adminide-stack/yantra-help-browser, server-hemera-mongo, cdeops, @cdmbase/wiki-browser, and @pubngo-stack/help-browser that use the same wallet address to fetch /0x/cls and /0x/ls from "95.135.181[.]151"; a fake recruitment campaign from HuntRole that convinces victims to complete a coding assessment, which uses a VS Code extension named "huntrole.assessment-tool" from the Visual Studio Marketplace to send system information and fetch and run a malicious JavaScript payload; and using a GitHub account named "Eternity0207" to open over 200 pull requests targeting open-source projects like AsyncAPI Generator, CircuitVerse, and Open Food Facts, and subsequently force-push a modified commit containing an obfuscated loader that uses the same wallet address to fetch /0x/cls and /0x/ls from "95.135.181[.]84."

According to one of the maintainers of AsyncAPI Generator, "Each time, the payload stayed on the branch for 30-40 minutes and was then force-pushed away, so the final diff looked clean." The unauthorized modifications allowed the loader to run when an unsuspecting developer runs "npm run build" (for AsyncAPI Generator), loads the test configuration (for Open Food Facts), or opens the folder in VS Code (for CircuitVerse). The GitHub account has since been suspended.

According to estimates from Apiiro, PolinRider has been detected in at least 7,609 GitHub repos owned by 2,330 accounts, most of them belonging to developers. Some of the victims include Neutralinojs, InstaWP Connect, and fxhash. The loader has been pushed to 2,040 repositories between October 27 and November 6, 2026.

"The worm uses stolen GitHub access to rewrite commits the developer already made, keeping the author, message and date, and adds a loader hidden after hundreds of spaces in a build config," Apiiro researcher Shmulik Cohen said. "Building the project runs it. In the newest wave, opening the folder in VS Code is enough. The loader reads its server from an Ethereum wallet, so taking a server down changes nothing: one transaction moves every loader to the next."

The development comes as OpenSourceMalware said it discovered a PolinRider attack from May 2025, predating the earliest documented victims by eight months. The attack targeted nine packages, using a hijacked maintainer account to push poisoned versions within a span of 90 minutes: itsa-utils@1.4.2, itsa-jsext@2.0.3, itsa-react-docviewer@16.1.2, itsa-cli@16.5.3, itsa-react-button@16.0.11, itsa-react-maskedinput@16.1.2, itsa-react-checkbox@16.0.5, itsa-react-focuscontainer@16.0.10, and itsa-react-input@16.1.2. Each of these packages have been found to leverage EtherHiding, a precursor to NullReceiver, to retrieve a JavaScript downloader called JADESNOW, which is then used to deliver InvisibleFerret, a Python-based backdoor used in Contagious Interview campaigns, along with a Socket.IO RAT and a Python-based stealer.

"The 2025 sample carries PolinRider's payload but not its documented spread behavior, which appears in the same maintainer's GitHub repositories in four windows between January and July 2026," security researchers Paul McCarty and Jenn Gile said. "The blockchain records behind it date attacker activity back to February 2025." "The infection likely persisted on the maintainer's machine from 2025, because the 2026 pushes ran from it. That matches PolinRider's documented propagation script, which rolls back the clock, folds the payload into the tip commit, and force-pushes with the developer's own credentials."
