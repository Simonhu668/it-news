Oracle E-Business Suite 12.2 在 19c CDB/PDB 架构下的数据库性能调优分步手册（作者：Bidhan Mandal，Oracle Core DBA / Apps DBA）。开始前三条铁律：一次只改一件事；每次变更前后都打 AWR 快照；改参数前先备份 SPFILE（CREATE PFILE FROM SPFILE），先在 UAT 环境测试。AWR/ASH/ADDM/SQL Tuning Advisor 需要 Diagnostics + Tuning 授权。15 步索引：1 操作系统/服务器（确认 CPU、内存、swap、I/O 不是瓶颈）；2 CDB/PDB 健康（实例、PDB 打开模式、告警日志）；3 实时会话与等待（查当前会话在等什么、谁阻塞了谁）；4 AWR/ASH/ADDM（按时间窗口定位瓶颈）；5 Top SQL 调优（修执行计划、用 SQL Tuning Advisor、固定基线）；6 优化器统计信息（按业务套件方式用 FND_STATS 收集）；7 内存（SGA/PGA 配比、HugePages）；8 初始化参数（对照 12.2 认证值，MOS Doc ID 396009.1）；9 Redo、TEMP、UNDO 与数据文件 I/O；10 应用层日常维护（并发管理器/工作流清理、大表）；11 ADOP 清理与失效对象；12 段与索引（回收站、不可用索引、碎片）；13 CDB 资源管理器与调度作业；14 中间层检查（OACore JVM、数据库连接池）；15 验证与归档（前后对比、变更记录）。快速分诊：db file sequential read → 执行计划差/缺索引/存储慢（走步骤 5、6、9）；log file sync → redo 盘慢或提交太频繁（步骤 9）；enq: TX 行锁争用 → 阻塞会话/定制代码（步骤 3、10）；library cache 闩锁 → 硬解析多、共享池小（步骤 7、8、11）；CPU 打满但等待少 → 烂 SQL/并行度/PDB CPU 限额（步骤 1、5、13）；只有并发请求慢 → 统计信息过期、FND 表膨胀（步骤 6、10）。步骤 3 关键只读查询：按等待事件汇总活跃会话（v$session，排除 Idle）；查阻塞会话（blocking_session 非空，按等待秒数排序；kill 前必须先与应用负责人确认）；查运行超 5 分钟的长会话。步骤 4：在 CDB$ROOT 打开 PDB 级 AWR 快照，快照间隔 30 分钟、保留 14 天；用 awrrpt/ashrpt/addmrpt 生成报告，用 awrddrpt 对比"好时段 vs 坏时段"；读 AWR 按顺序：负载画像（DB Time vs 经过时间）、Top 10 前台等待事件、SQL 按耗时排序、实例效率（软解析率应大于 95%）。步骤 5：从 v$sql 按耗时找 Top SQL，用 DBMS_XPLAN 看执行计划（含 AWR 历史计划），同一 sql_id 出现多个 plan_hash_value 说明计划变了；用 DBMS_SQLTUNE 建调优任务；好计划用 DBMS_SPM 固定为基线。特别说明：不要改 Oracle 预置的 SQL，靠统计信息、官方支持建议的索引、基线或官方补丁修；自研（XX）代码可以重写。步骤 6：应用 schema 一律用并发请求"收集 Schema 统计信息"（FND_STATS），不要直接用 DBMS_STATS，保证直方图处理正确；低峰期跑，建议每周一次。步骤 15 验证与归档：变更前后打快照、用 awrddrpt 生成对比报告，记录指标（平均活跃会话、DB Time/经过时间、Top 等待事件、关键并发请求耗时）与变更内容/日期/执行人；回滚用备份的 PFILE 恢复参数。

Oracle EBS 12.2 on 19c CDB/PDB - Database Performance Tuning, Step-by-Step DBA Runbook. Prepared by: Bidhan Mandal | Oracle Core DBA & Apps DBA. Rules before you start: Change ONE thing at a time. Take AWR snapshot before and after every change. Backup SPFILE (CREATE PFILE FROM SPFILE) before parameter changes. Test in UAT first. AWR/ASH/ADDM/SQL Tuning Advisor need Diagnostics + Tuning Pack licence. Step Index: 1 OS/Server - confirm CPU, memory, swap, I/O are not the bottleneck; 2 CDB/PDB health - instance, PDB open mode, alert log, errors; 3 Live sessions & waits - find what sessions wait on right now, blockers; 4 AWR/ASH/ADDM - find bottleneck over time window; 5 Top SQL tuning - fix bad plans, use SQL Tuning Advisor, SPM baseline; 6 Optimizer statistics - EBS-correct stats gathering (FND_STATS); 7 Memory (SGA/PGA) - right-size, HugePages; 8 Init parameters - validate against EBS 12.2 certified values; 9 Redo, TEMP, UNDO, datafile I/O - remove storage-side waits; 10 EBS application housekeeping - concurrent manager/workflow purge, big tables; 11 ADOP cleanup & invalid objects; 12 Segments & indexes - recycle bin, unusable indexes, fragmentation; 13 CDB resource manager & scheduler jobs; 14 Middle tier check - OACore JVM, DB connection pool; 15 Validate & document - before/after comparison, change log. Quick Triage Table: db file sequential read -> bad plan, missing index, slow storage (steps 5,6,9); db file scattered/direct path read -> full scans, stale stats, small buffer cache (5,6,7); log file sync/parallel write -> slow redo disk, too frequent commits (9); enq: TX row lock contention -> blocking session/custom code (3,10); library cache mutex X/latch shared pool -> hard parse, small shared pool, invalids (7,8,11); CPU 100% with few waits -> bad SQL, parallelism, PDB CPU limit (1,5,13); resmgr:cpu quantum -> Resource Manager throttling PDB (13); slow only in concurrent programs -> stale stats, FND tables bloated (6,10). Step 3 live sessions (read-only SQL): SELECT event, wait_class, COUNT(*) FROM v$session WHERE status='ACTIVE' AND type='USER' AND wait_class<>'Idle' GROUP BY event, wait_class; blocking sessions: SELECT blocking_session, sid, serial#, event, seconds_in_wait, sql_id, module FROM v$session WHERE blocking_session IS NOT NULL ORDER BY seconds_in_wait DESC (kill only after confirming with application owner); long-running sessions > 5 min via last_call_et. Step 4 AWR: enable PDB-level snapshots (ALTER SYSTEM SET awr_pdb_autoflush_enabled=TRUE), snapshot every 30 min keep 14 days, generate awrrpt/ashrpt/addmrpt, compare good vs bad window with awrddrpt; read order: Load Profile, Top 10 Foreground Events, SQL ordered by elapsed time, Instance Efficiency (soft parse % > 95%). Step 5 Top SQL: find top SQL from v$sql ordered by elapsed_time, check plan with DBMS_XPLAN.DISPLAY_CURSOR / DISPLAY_AWR, detect plan changes (multiple plan_hash_value per sql_id), run DBMS_SQLTUNE tuning task, pin good plan with DBMS_SPM.LOAD_PLANS_FROM_CURSOR_CACHE. EBS note: do not edit Oracle seeded SQL - fix with stats, indexes recommended by Oracle Support, baselines, or an Oracle patch; custom (XX) code can be rewritten. Step 6 stats: for EBS application schemas always gather with concurrent program 'Gather Schema Statistics' (FND_STATS), not raw DBMS_STATS, so histograms and EBS-specific handling are correct; run during low load, schedule weekly. Step 15 validate & document: take end snapshot, generate after-change AWR, record before/after metrics (avg active sessions, DB Time/elapsed, top wait event, key concurrent program runtime), change made/date/by; rollback: keep the PFILE backup from step 7, ALTER SYSTEM SET <param>=<old> SCOPE=SPFILE or CREATE SPFILE FROM PFILE, restart.
