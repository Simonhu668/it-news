正文 · AI 翻译

微软威胁情报披露了两起手动入侵，两起入侵的起点相同：攻击者通过 Teams 消息与电话冒充 IT 或技术支持人员，诱使员工授予计算机远程控制权限，主要通过 Quick Assist 实现。连接建立后，入侵者投放便携式编程运行环境，摸清主机与网络，并探查组织的证书基础设施，寻找提权路径。两起案例的意义在于，一次被批准的支持会话可以演变为以证书为凭据的特权账户与核心域系统控制。微软强调，没有 Teams 漏洞被利用，攻击依赖说服手段，以及 Active Directory 证书服务（AD CS）不安全或过于宽松的配置；微软未把活动归因于任何特定威胁行为体。攻击者使用的外部联系方式采用与目标组织相似的 Teams 租户名，以及听起来像支持团队的显示名，使其看起来熟悉。受害者被引导打开 Quick Assist 并分享连接码，攻击者由此获得工作站的实时键盘控制。微软称远程会话是决定性转折点：攻击者把一个压缩包放入用户 Downloads 文件夹，在用户配置文件内创建一个以 KB 开头的文件夹并在其中解压，再用便携式 Python、JavaScript 或 Java 运行环境启动载荷；其中一个变种里，被改名的可执行文件仍带有可识别为 Bun JavaScript 运行环境的版本信息。投放的代码随后运行常见命令，收集 Windows 版本信息、网络设置与运行进程，工作站通过 LDAPS 与 SMB 连接域基础设施。微软指出，这类命令对管理员而言是常规操作，但当改名后的运行环境从异常文件夹启动、且紧跟一次意外的支持会话时，其调查权重会大得多。AD CS 是签发用于认证的数字证书的 Windows Server 角色。微软解释，为特权用户或计算机签发的证书独立于该账户的密码发挥作用：重置密码或重装首台受感染计算机，既不会吊销证书，也不会取消已签发的 Kerberos 票据。第一起案例中，攻击者找到一个存在 ESC1 缺陷的证书模板，该配置允许申请者指定证书应当代表的身份，于是拥有广泛注册权限的低特权账户可以为管理员取得证书。微软报告称，攻击者在首波中为 3 个高度特权账户取得证书，约 90 分钟后针对 16 名用户的更大规模 Teams 钓鱼又取得 8 张证书。微软 Defender 的自动攻击阻断限制了受影响身份，限制远程登录与 SMB 访问、断开活动会话，并拦截了 1,000 余次后续 SMB 文件访问尝试；但在获得一张特权证书数秒后，攻击者即对域控制器执行 DCSync（模拟域控制器之间复制以拉取凭据数据的技术）。一个特权账户被排除在自动遏制之外，微软称攻击者用该账户访问文件服务器，并用改名后的 Rclone 工具副本向外部 SFTP 服务器复制数据。第二起案例走了不同路线，因为该环境中没有 ESC1 路径：攻击者用 PetitPotam 技术诱使域控制器向攻击者控制的系统认证，再把该 NTLM 登录中继到 AD CS Web 注册服务，即 ESC8 攻击；攻击者取得域控制器证书，并用其换取该计算机的 Kerberos 票据授予票据。第二起案例中，Defender 发出 ESC8 相关告警，客户隔离了相关工作站，此后未观察到进一步进展；微软将其与第一起案例对比，第一起中一个排除项就在遏制其余身份之后仍留下一条可用的特权路径。人员方面，微软建议用户在接受来电或远程会话前，通过已知内部渠道核实未经请求的支持请求，检查 Teams 外部访问策略，把远程支持工具限定为经批准的产品与流程，并用应用控制拦截从用户可写文件夹运行的未经批准便携式运行环境。证书服务方面，微软建议审计可用于认证的模板，检查是否存在申请者指定身份与广泛注册权限，移除不需要的 Web 注册端点；剩余端点应当要求 HTTPS 与扩展保护认证（把登录绑定到其所在的特定连接，使中继登录更难被重复使用；仅用 HTTPS 只能保护保密性，不能提供这种绑定）。如果已签发流氓证书，微软称响应方应当吊销证书、发布更新后的吊销信息，并另外检查活动中的 Kerberos 票据，因为吊销不会使已发出的票据失效；同时应当枚举每一个受损身份与设备，并在响应前与响应中检查遏制排除项，因为第一起案例表明，一个被排除的账户即可保留攻击者的路线。

原文

Microsoft Threat Intelligence has described two hands-on intrusions that began the same way. Attackers contacted employees through Microsoft Teams messages and calls while posing as IT or help desk staff. They persuaded those employees to grant remote control of their computers, mostly through Quick Assist. Once connected, the intruders probed the organization's certificate infrastructure for a way to escalate. Microsoft stresses that no Teams vulnerability was exploited. The attacks depended on persuasion and on insecure or overly permissive AD CS configurations. Victims were guided to open Quick Assist and share the connection code. The attacker staged a portable runtime from the user's profile folder. AD CS is a Windows Server role that issues digital certificates used for authentication. Microsoft explains that a certificate issued for a privileged user or machine works independently of that account's password: resetting the password or reimaging the first infected computer neither revokes the certificate nor cancels Kerberos tickets already issued. In the first case, the attacker found a certificate template vulnerable to ESC1, which lets a requester name the identity a certificate should represent, so a low-privileged account with broad enrollment rights can obtain a certificate for an administrator. The attacker obtained certificates for three highly privileged accounts in an initial wave, then for eight more after a larger Teams phishing push against 16 users roughly 90 minutes later. Microsoft Defender's automated attack disruption restricted the affected identities. But seconds after receiving one privileged certificate, the attacker performed DCSync against a domain controller. One privileged account had been excluded from automated containment, and Microsoft says the attacker used it to reach a file server and copy data to an external SFTP server with a renamed copy of the Rclone tool. The second case used PetitPotam to trick a domain controller into authenticating to an attacker-controlled system, then relayed that NTLM login to the AD CS web enrollment service, an attack known as ESC8. The attacker obtained a certificate as the domain controller and used it to get a Kerberos ticket-granting ticket for that machine. In the second case, isolation after ESC8 alerts stopped further progression. Microsoft advises users to confirm unsolicited support requests through a known internal channel before accepting calls or remote sessions, and to limit remote-support tools to approved products. For certificate services, Microsoft recommends auditing templates, removing unneeded web enrollment endpoints, and requiring HTTPS and Extended Protection for Authentication on remaining endpoints. If a rogue certificate was issued, responders should revoke it, publish updated revocation information, and separately review active Kerberos tickets, and check containment exclusions before and during a response.
