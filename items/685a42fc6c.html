Windows 远程访问 API 中的一个缺陷可让已能在设备上运行代码的攻击者以 SYSTEM 权限执行代码。微软已在 11 月 10 日的 2026 年 11 月补丁星期二更新中修复 CVE-2026-119853，评级为 Important，CVSS 基础分 7.8；修复覆盖受影响的 Windows 10、Windows 11 与 Windows Server 版本。

尽管组件名为远程访问，这并不意味着攻击者可从互联网直接攻入 Windows 设备。攻击者须已能在受影响设备上运行代码，但无需管理员权限，也无需其他用户协助。一旦拿到立足点，以 SYSTEM 运行的代码可访问受保护文件、修改标准用户无法更改的设置。

Windows 远程访问服务（RAS）管理 VPN 等连接，把连接设置存放在配置文件中，并支持用于自定义连接处理的软件库。微软将该缺陷归类为“不受信任的搜索路径”：特权 Windows 组件可能从攻击者可影响的位置加载代码。问题不在于用户能修改自己的连接设置，而在于 Windows 可能以服务权限运行用户控制的代码。

Core Security 在 11 月 23 日的文章中报告，Windows 服务宿主加载了研究人员控制的动态链接库（DLL），以 SYSTEM 账户运行；研究人员确认该结果出现在 Windows 11 Pro 25H2（内部版本 26200.9711）上，且无需实时 VPN 连接或互联网连接。该发现与 PhantomRPC 不同，后者是另一个服务边界上的 Windows 提权问题。

微软首次发布公告时称未观察到利用行为，但将利用可能性评为“更可能”。研究演示证明该缺陷在测试条件下可被利用，但不能证明攻击者已在真实系统上使用它。这一点也把它与 SignDrop 的公开情况区分开来。

管理员应安装适用的 11 月安全更新或包含该修复的后续累积更新；微软安全公告按 Windows 版本列出更新包与内部版本号。例如 Windows 10 22H2 对应 KB5131096（内部版本 19045.7846），Windows Server 2022 对应 KB5131090（内部版本 20348.5870）。可用 Windows 发布健康信息核对已安装版本与该版本的更新历史；不要把修改 VPN 配置文件当作打补丁的替代品。

更新铺开期间，安全团队可检查端点日志，看 Windows 服务宿主是否从普通用户可写的位置加载了异常 DLL；如有此类活动，核查库文件的路径与签名，并检查服务宿主在相近时间启动的进程。

原文

A vulnerability in the Windows Remote Access API lets an attacker with limited access to a computer run code with SYSTEM privileges. Microsoft fixed CVE-2026-119853 on November 10 as part of its November 2026 Patch Tuesday updates. The company rated the flaw Important and assigned it a CVSS base score of 7.8. Updates cover affected releases of Windows 10, Windows 11, and Windows Server.

Despite the component's name, this does not allow an attacker to break into a Windows machine over the internet. An attacker must already be able to run code on the affected device, but does not need administrator rights or help from another user. The flaw matters after that first foothold: code running as SYSTEM can reach protected files and change settings that a standard user cannot.

Windows Remote Access Service, or RAS, manages connections such as VPNs. It stores connection settings in profiles and supports software libraries that customize how connections are handled. Microsoft classifies the flaw as an untrusted search path, meaning a privileged Windows component can load code from a location an attacker can influence. The security failure is not that a user can change their own connection settings. It is that Windows can end up running user-controlled code with the service's permissions.

In its November 23 write-up, Core Security reported seeing a Windows service host load a researcher-controlled dynamic-link library, or DLL, under the SYSTEM account. The researchers reported confirming the result on Windows 11 Pro 25H2, build 26200.9711, without a live VPN or internet connection. That finding reinforces the difference between the feature involved and the access an attacker needs. For comparison, PhantomRPC is a separate Windows privilege escalation issue involving a different failure at a service boundary.

Microsoft said it had not observed exploitation when it first published the advisory, although it rated exploitation "More Likely." A research demonstration shows that the flaw can be exploited under test conditions. It does not establish that attackers have used it against real systems. That distinction also separates this case from the claims surrounding the Windows SignDrop disclosure.

Administrators should install the applicable November security update or a later cumulative update that includes the fix. The Microsoft security advisory lists update packages and build numbers by Windows release. For example, Microsoft lists KB5131096 for Windows 10 22H2, bringing it to build 19045.7846, and KB5131090 for Windows Server 2022, bringing it to build 20348.5870. Use Windows release health to check the installed build against that version's update history. Do not treat changes to VPN profiles as a substitute for patching.

While updates roll out, security teams can review endpoint logs for Windows service hosts loading unexpected DLLs from locations ordinary users can write to. Where that activity appears, check the library's path and signature, then review any processes the service host started around the same time.
